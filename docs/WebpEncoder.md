# WebP 有损编码器（VP8）现状与缺口

本文件记录**纯托管 VP8 编码器**（`src/Formats/Webp/Vp8Encoder.cs`）的实现边界、与 libwebp
的实测差距，以及按优先级排列的补齐清单。解码侧与 VP8L 无损侧见 `PerfReport.md` §6.5。

## 1. 已实现

| 环节 | 现状 |
|---|---|
| 帧头 / 量化表 | 1 个 token 分区；`quality → q index` 单调映射；环内滤波强度按 q 分档 |
| 帧内预测 | 16×16：DC / TM / V / H；8×8 色度同四种；**4×4（B_PRED）10 种模式** |
| 模式选择 | 像素域 SSE 最小（16×16 与 i4x4 之间用 SSE 门槛取舍，见 §3） |
| 变换量化 | 4×4 整数 DCT，Y2 二次变换，标量量化 |
| 熵编码 | 标准 Huffman 表 + 两遍法（第一遍统计 0/1 频次，第二遍自适应概率写位流） |
| 滤波 | 环内滤波对齐解码端顺序，宏块边界（16×16 帧内不启用宏块内部边界） |
| alpha | ALPH 平面 VP8L 无损编码，支持四种预测过滤并自动择优 |
| 两遍决策一致性 | 第一遍 `statsOnly` 只统计、不滤波，且与第二遍共用同一套模式决策 |

## 2. 与 libwebp 的实测差距

1024×1024，同 q，体积比 = 我方 / libwebp（<1 表示我方更小）。

| 内容 | q50 | q75 | q90 | q95 |
|---|---|---|---|---|
| 自然照片 photo | 0.968 | 1.209 | 0.938 | 1.030 |
| UI 截图 ui | 0.862 | 1.014 | 0.981 | 0.982 |
| 合成渐变 grad | 0.665 | 0.940 | 0.958 | 1.152 |
| 文字截图 a_text | 0.922 | 1.197 | 1.044 | 1.072 |
| 纯色面板 rgba_panel | 1.638 | 2.044 | 2.172 | 2.784 |
| 柔渐变 rgba_softgrad | 0.621 | 0.691 | 0.714 | 0.814 |

注意同 q 下我方 PSNR 普遍低 0.2~0.6 dB，所以上表不是等画质比较；等画质上我方的优势会缩小。
**纯色面板类仍差 1.6~2.8×**，是当前最大的单点差距。

## 3. i4x4 的取舍门槛

`ShouldUseI4x4`：i4x4 需把宏块 SSE 压到 16×16 的 55% 以内才采用。

标定：6 张 1024² × q50/75/90/95 共 24 组，只改门槛：

| 门槛 | 总体积 | 平均 ΔPSNR |
|---|---|---|
| 0（关闭 i4x4） | 基线 | — |
| 40 | −6.81% | +0.074 dB |
| **55（采用）** | **−7.48%** | **+0.087 dB** |
| 70 | −6.71% | +0.114 dB |
| 85 | −4.85% | +0.138 dB |
| 100（有改善就用） | −2.78% | +0.159 dB |

**已知局限**：最优门槛随内容漂移——自然照片偏 40（χ=40 时 photo 各档 −7.1/−12.2/−11.5/−7.5%），
UI 截图偏 70~100（ui 各档在 100 时 −11.4/−13.5/−12.1/−12.5%）。单一像素域门槛无法表达
「模式位 vs 残差能量」的兑换率，属于 §4 第 1 项的范畴。

代价：1024² q75 编码 78 → 110 ms（+41%）。试排对每个宏块都要跑一遍；被否决的宏块还要
把 16×16 的预测与残差重做一次（两条路的重建结果不可共用）。`sse16 == 0` 时精确提前退出。

## 4. 缺口（按优先级）

1. **RD 优化**：把「量化误差 + λ·码率」作为决策目标，替代当前的像素域 SSE 门槛：
   - i4x4 / 16×16 取舍与 4×4 模式选择都用 RD 成本（模式位可用真实概率算 −log₂p，
     系数码率可用 nz 计数或 trellis 的 DP 代价）；
   - 分段自适应量化（`rgba_panel` 的 2× 差距主要来源：libwebp 把平坦区与边缘区
     分到不同 segment，用不同量化步长）；
   - 滤波强度参与率失真（当前按 q 查表定死）。
2. **无损编码多 pass**：直方图二次优化（用第一遍的实际码长重算 Huffman）、长窗 LZ77。
3. **CLI `--webp-lossless` 与 `SaveOptions.WebpLossless`**：编码器支持无损，但入口未暴露。
4. **动图解码改按帧流式**：当前每帧 `canvas.ToArray()`，内存 O(帧数 × 画布)。
5. **静态 VP8X canvas 尺寸与帧尺寸交叉校验**。
6. **`WebpEncoderAdapter(.Rgba)` 的三个 setter 丢失 `Lossless`**。
7. **文档漂移**：`WebpDecoder` 类注释、`WebpContainer.Vp8` 枚举注释与实现不符。

## 5. 踩过的坑

- **B_PRED 模式树写错一位就整体错位**：解码端 `kBModesProba` 的树里 B_HE 需要
  `p0..p2=1, p3=0, p4=0` 共 5 位，写侧曾漏掉最后一位。表现是 64×64 q75 的 PSNR 从
  40.7 掉到 12.0 dB，而两支解码器（我方 + libwebp）互相一致——位流合语法，只是模式读错。
  定位方法是给布尔编/解码器加位级 trace（记录 `(bit, prob, 语法段)`），第 1364 位处
  编码端用 `p[0][3][0]=56`、解码端用 `p[1][9][4]=197`，由此反推出「解码端多读了一位」。
  现已把模式树抽成 `Vp8ModeTree` 单一实现，并加全组合往返测试。
- **i4x4 的重建与模式选择必须逐块交错**：子块 n 的预测要读已重建的 n−1 / n−4，
  不能先算完 16 个子块的 SSE 再统一变换（那不成立）。因此「先判定再选路」不可能省掉
  被否决宏块的重复工作。
- **`top_right` 的三个写入位置是第 3/7/11 行右侧**（对应 C 里 `top_right` 指针按 BPS
  步进），不是第 0/4/8 行；最右列宏块要把上一行右侧 padding 归一化为边缘像素，
  否则下次读到陈旧值。
