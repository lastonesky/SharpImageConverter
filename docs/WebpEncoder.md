# WebP 有损编码器（VP8）现状与缺口

本文件记录**纯托管 VP8 编码器**（`src/Formats/Webp/Vp8Encoder.cs`）的实现边界、与 libwebp
的实测差距，以及按优先级排列的补齐清单。解码侧与 VP8L 无损侧见 `PerfReport.md` §6.5；
VP8L 位流规范与逐条对照结论见 `WebPLoseless.md` 与 `WebpConformanceReview.md`。

## 1. 已实现

| 环节 | 现状 |
|---|---|
| 帧头 / 量化表 | 1 个 token 分区；`quality → q index` 单调映射；**4 段分段量化**按 16×16 活动度分类，段 delta `{+2,+1,+1,+1}`（见 §3.5）；**partition0 降级（关闭分段）时所有段回退基础 q**——降级路径所有宏块都在 segment 0，若仍叠加段 delta，整图粗两档，色度 DC 预测误差在平坦区落入死区无法修正，会扩散成大面积粉紫偏色 |
| 帧内预测 | 16×16：DC / TM / V / H；8×8 色度同四种；**4×4（B_PRED）10 种模式** |
| 模式选择 | **率失真（D + λ·R）**：i4x4 与 16×16 各自完整编码一遍，按重建失真 + 精确码率决胜（见 §3） |
| 变换量化 | 4×4 整数 DCT，Y2 二次变换；**系数 trellis 量化**（块内 DP + RD 代价，见 §3.6）；量化取整与 libwebp `ExpandMatrix` 同口径（类型偏置 + 亮度 AC 频率锐化），DC 电平按 IDCT 的**真实重建量**择优（见 §3.8） |
| 熵编码 | 布尔算术编码器（bool coder），token 概率两遍法：第一遍统计 0/1 频次，第二遍把更新后的概率写进帧头 |
| 滤波 | 环内滤波对齐解码端顺序，宏块边界（16×16 帧内不启用宏块内部边界）；**滤波强度按实测滤波后 SSE 选择，并按段写 lf delta**（见 §3.7） |
| alpha | ALPH 平面 VP8L 无损编码，支持四种预测过滤并自动择优 |
| 两遍决策一致性 | 第一遍 `statsOnly` 只统计、不滤波，且与第二遍共用同一套模式决策 |

## 3. 率失真决策（RD）

每个宏块把 i4x4 与 16×16 **都完整编码一遍**（预测 → 变换 → 量化 → 重建），各自得到：

- **D**：重建后的亮度 SSE（不是模式选择用的预测域 SSE——两者不是一回事）；
- **R**：这一路写出去要多少 bit，由「只累加成本、不产出字节」的编码器实例算出。

取 `D + λ·R` 小者。胜者若是 i4x4，就从备份恢复它的重建块与量化数组（16×16 那遍已经把
重建平面覆盖了）。

### 3.1 码率估计复用真实写位函数

给 `Vp8BoolEncoder` 加了成本模式：`BeginCost()` 之后 `PutBit` 只累加
`-log₂P(bit)`（查 `Vp8CostTable`，单位 1/256 bit，全程整数避免跨平台分叉），
不改 range/value。于是 `CostLuma` 可以把 `_part0`/`_tokens` 临时换成这个实例，
**直接复用** `WriteMacroblockModes` / `WriteResidualTokens` / `Vp8ModeTree.Write` ——
码率模型与位流生成是同一段代码，不可能失配。试算结束后回滚 nz 与 i4x4 模式上下文。

精度实测：选中的每一路「估计位数 / 实际写出位数」= **1.00**（grad/photo 差 <0.1%）。

代价是每个宏块多跑两遍写位逻辑（一遍计价、一遍真写），1024² q75 从 110 ms 涨到 128 ms。

### 3.2 踩过的坑：概率语义反了

`Vp8CostTable` 第一版把 VP8 的 `prob` 当成 P(bit=1) 建表，实际它是 **P(bit=0)**
（编码端 bit=0 取 `[0, split)`，split 正比于 prob）。结果常见事件被算成昂贵：
整体成本**高估 4.75 倍**，而且高估倍数随内容漂移（渐变图 4.7×、照片 2.8×）。
后果是 RD 反而比原来的 SSE 门槛差 5%——i4x4 被当成便宜货过度使用。

定位方法：直接对比「估计位数」与「实际写出的位数」（`_part0.Length + _tokens.Length`
的增量），比值 4.75 一眼看出问题不在决策逻辑而在成本模型。

### 3.3 λ 标定

`λQ8 = LambdaScale × y1Ac`：λ 与量化步长成正比（量化越粗，1 bit 能换回的失真越多）。
6 图 × q50/75/90/95 共 24 组，对照旧的「SSE 压到 16×16 的 55% 以内」门槛：

| LambdaScale | 总体积 | 平均 ΔPSNR | 劣于旧门槛的组数 |
|---|---|---|---|
| 150 | −3.04% | +0.010 dB | 0/24 |
| 230 | −3.09% | −0.003 dB | 0/24 |
| **300（采用）** | **−3.11%** | **−0.010 dB** | **0/24** |
| 350 | −3.13% | −0.014 dB | 1/24 |
| 450 | −3.10% | −0.022 dB | 0/24 |
| 600 | −3.15% | −0.026 dB | 0/24 |

曲线在 150~600 之间几乎是平的（体积极差 0.11%）。**这是 RD 相对旧门槛最重要的差别**：
旧门槛的最优值随内容大幅漂移（自然照片偏 40、UI 截图偏 70~100），换一批图就得重标；
RD 的 λ 按量化步长缩放后，整段区间都能用。

引入分段量化后，λ 使用当前宏块所在 segment 的 `y1Ac`（粗段量化步长更大，λ 相应变大），
统计遍与产出遍的分段判定都只依赖源平面，两遍一致。

`sse16 == 0`（整块完全平坦）时跳过 i4x4 试排——这是精确的提前退出，不是门槛。

### 3.4 4×4 子块模式 RD

每个子块先对 10 种预测求 SSE，保留前三名。三个候选分别变换、量化和重建，
按重建 SSE 加上模式位与系数位成本选择，再恢复胜者作为后续子块的预测源。
模式成本复用 `Vp8ModeTree.Write`，系数成本复用 `WriteCoeffs`；试算使用局部的
上方/左方模式和非零上下文，不更新真实编码上下文或第一遍统计计数。

三张现有照片各测 q75/q90，与原 SSE 搜索相比，同 q 体积减少 2.57%~5.55%，
PSNR 变化为 −0.009~+0.167 dB。这是同 q 的小样本结果，不能当作等 PSNR 的总体收益。
候选多次变换会增加编码耗时，仍需更大语料和稳定基准评估。

### 3.5 分段量化（重做为 4 段）

首版两段实现（阈值方差 <1、delta ≤6）没有收益：入选宏块残差全零、本来就走 skip，
粗化它们的量化步长省不到任何位，反而要付 segment map 的码率。重做后：

- **4 段**，按 16×16 源亮度方差分档：`<0.25` / `<1` / `<4` / 其余，依次是纯色、
  近平坦、低频渐变、纹理。边缘宏块按实际有效像素数归一化方差。
- 段量化 delta `{+2,+1,+1,+1}`（`segment_feature_mode=0`，相对 base_q），λ 按所在段的
  `y1Ac` 缩放；segment map 树的三处概率由实际分布统计后写进帧头。
- 与首版的关键区别是阈值放宽到方差 <4，覆盖 UI 底色、柔边等「低细节但**有**非零残差」
  的宏块——这正是首版圈不到、libwebp 用分段省码率的地方。

结果（§2 24 组，同轮还叠加了 trellis，未做单独消融）：`rgba_panel` 相对 libwebp
从 1.500/1.897/2.004/2.661 降到 0.868/0.890/1.025/0.734；24 组总体积 −9.37%，
平均 PSNR +0.070 dB，无单组增长。

### 3.6 系数 trellis 量化

`Vp8Trellis.Quantize` 在块内做**真正的动态规划**，不是逐系数贪心：

- 状态 `(m, ctxAfter)`：`m` 是当前系数位置（0..15），`ctxAfter` 是量化后的
  「后续非零上下文」三元状态（上一系数非零 / 前两个非零 / 其余），共 `17×3 = 51` 个。
- 每个系数的候选电平 `{0, q−2, q−1, q, q+1, q+2}`（`q` 为标量量化结果），
  状态转移成本 = 系数域失真 `(c − level·dq)²` 的加权和 + λ·R；
  R 由 `Vp8CostTable` 的 EOB / 非零 / 大幅值节点成本精确累加（单位 1/256 bit）。
- `λQ8 = 36 × dq`（亮度 AC/DC、Y2、色度各自取所在块的步长）；`TrellisLambda`
  由 24 组对照从 {8,16,24,32,48} 中选定——更大的值换体积但高 q 照片掉 PSNR。
- 输出同时写量化电平和反量化槽位，预测/重建与熵编码使用同一份结果；
  工作区 `Vp8TrellisScratch` 每编码器独占，逐块零堆分配。
- 已接入亮度 Y1、Y2（WHT 后）、i4x4 子块与色度 U/V 四条量化路径。

系数域失真是重建 SSE 的线性近似（VP8 整数 IDCT 非严格正交），DP 用它保持
「同一块内能量守恒」的单调性；实际模式选择仍以重建后的像素域 SSE 决胜。

实现上（2026-11-06 优化，输出与旧版逐位一致）：空档位成本按块预计算
（h0/h1 头部 + 零游程前缀和，内层 O(1) 取差，原为每个 n 重算整段的 O(n²)
BitCost 查询）；候选电平、`NonZeroCost` 与量化误差平方提到位置级预计算
（原在每个状态内重复）；`Vp8CostTable` 展平为一维表。内核基准 65536 块
492.6 → 150.1 ms（3.28×），端到端有损编码 1.21~1.69×，见 `PerfReport.md` §6.8。

### 3.7 滤波强度参与 RD + 按段 lf delta

滤波强度不再由 q 查表定死（`EstimateFilterLevel` 只作为候选起点）：

- 候选 `{0, est/2, est, est·2, 48, 63}` 去重后，逐个对第一遍重建平面 `FilterAll`，
  实测**滤波后**相对源图像的加权 SSE（`4·Y + U + V`，对应 4:2:0 采样比），取最小。
- 再以选定的 base level 测 4 组按段 lf delta 候选
  `{0,0,0,0}` / `{+2,+1,0,−2}` / `{+4,+2,0,−4}` / `{−2,−1,0,+2}`（平坦段加强、
  纹理段减弱），同样按实测 SSE 选优；全 0 候选保证不会比全局强度更差。
- 帧头按 `segment_feature_mode=0` 写 4 个 lf delta（每段「是否非零」+ 6 位符号/幅值），
  解码端逐宏块按段合成 level，边界滤波使用当前宏块的 level，与解码端 `FilterRow`
  的顺序一致。
- 第一遍 `statsOnly` 不滤波，第二遍用同一 base level 与同一组 delta。

代价是每张图多 9 次全帧滤波（纯内存带宽操作）；24 组实测总量仅 +12 B（帧头位），
平均 PSNR 变化 <0.001 dB——按段 delta 在当前语料上基本不改变产物，但把
「滤波强度可参与 RD」这条路径做成了可标定的闭环，且不劣于全局强度。

### 3.8 量化取整口径与 DC 真实重建量

这两个口径都不是「调参」，而是与解码端的整数运算对齐；改之前的表现都是**位流合法、
两支解码器互相一致、但画质/体积反常**。

**（1）带偏置的量化（对齐 libwebp `ExpandMatrix` / `QuantizeBlock_C`）**

libwebp 的量化不是四舍五入，而是按系数类型各带一个偏置
（`kBiasMatrices[3][2] = {{96,110},{96,108},{110,115}}`，单位 1/256，行 = Y1/Y2/UV）：

```
level = (|coeff| * iQ + (bias << (QFIX-8))) >> QFIX      // QUANTDIV，QFIX = 17，iQ = (1<<17)/dq
```

亮度 DC 偏置最小（0.375，DC 更准），色度整体最钝（0.43/0.45）。差别看着只有 0.07 个
量化步，但它决定**残差落不落在死区**：色度 DC 的残差在平坦区稳定在 ±1~2，步长 30 时
`2/30 = 0.533`——按 0.5 取整会一直量化到相邻电平，每个块反向过冲 2 个灰度级，下一个块
再跳回来，于是整片纯色每块都买一个 token（1024² 纯色 1.8 KB → 4.2 KB，PSNR 反而更低）。

亮度 AC 另加频率锐化（`kFreqSharpening[16]`，`SHARPEN_BITS = 11`）：量化前把中频系数
幅值按 `(kFreqSharpening[n] * dq) >> 11` 抬高，换边缘/纹理的主观锐度。libwebp 的
`ExpandMatrix` 里只有 `type == 0`（亮度）拿得到这张表，本实现对应 `type == 0 || type == 3`。

Y2（WHT）的量化步长不是 luma 的整数倍：DC 正好 ×2（`kDcTable[q] * 2`），AC 走独立的
`kAcTable2` 曲线（比值从 q=0 的 2.0 一路降到 q=120 的 1.42）。历史实现用
`AcQuantTable[q] × 101581 >> 16`（≈×1.55）再加 `Max(8, …)` 拟合，实测与 `kAcTable2`
**128 个下标逐项相等**，现在直接内嵌原表、去掉魔数（输出不变）。

**（2）DC 电平按 IDCT 的真实重建量择优**

解码端 `TransformDC` 是 `(dc + 4) >> 3`，`dc = level · dq`。这个映射**不是线性的**：

| dq | level | dc | 重建（灰度级） | 系数域看 |
|---:|---:|---:|---:|---|
| 13 | 1 | 13 | 2 | 8/13 = 0.62 个电平 |
| 25 | 1 | 25 | 3 | 1.0 个电平 |
| 35 | 1 | 35 | 4 | 0.9 个电平 |

「残留 1、dq 13」在系数域够 0.62 个电平（该四舍五入到 1），但像素域要么不动、要么跳
2 格——跳过去就过冲 1 格，下一个块再反着跳回来，形成逐块买 token 的**极限环**。
所以 DC 位置的电平必须按 `Vp8Quant.DcRecon(level, dq) = (level·dq + 4) >> 3` 的真实
重建量比较误差，而不是按系数比取整：

```csharp
int lower = sign * (|coeff| * iQ >> QFIX);      // 不带偏置的最近格
int upper = lower + sign;
q = DcPixelError(coeff, upper, dq) < DcPixelError(coeff, lower, dq) ? upper : lower;
```

只比两格就够：`DcRecon` 随电平单调不减，单电平至少挪 `dq/8 ≥ 0.5` 个灰度级（dq ≥ 4），
失真随电平先降后升。误差按**带符号**的真实重建量算——`(dc+4) >> 3` 正负不对称
（`dc = 204` 时 `+26`、`−25`），取绝对值会差一格。Y2 的 DC 走 WHT 分发、重建映射不同，
不做这一步；trellis 的 DC 失真项按同一个 `DcRecon` 折算。

**（3）纯 DC 色度块跳过 trellis**

libwebp 的 `DO_TRELLIS_UV 0` 是「色度不做 trellis」的口径，理由是风险大于收益。本实现
只对**AC 全零**的色度块走标量量化（`IsAcZero`），有 AC 的块仍走 trellis：实测全量关掉
UV trellis 反而略差（`ui`/`a_text` 的色度细节变糊），而纯 DC 块正是极限环的源头。

**（4）扫过的参数（未采纳）**

`UvDcDeltaQ` 从 −2 扫到 −3/−4（色度 DC 再细 1~2 档）：24 组平均 PSNR +0.23/+0.49 dB、
体积 +0.04%/+0.12%，但收益几乎全部来自**单个电平的巧合对齐**——纯色 q75 在 −4 时
PSNR +12.3 dB（40.6→52.9）、q90 时 −2.6 dB，`ui` q90 则要多花 8.1% 位。没有系统性
收益，保持 −2（与 libwebp 黑盒观测一致）。

## 4. 缺口（按优先级）

1. **无损 LZ77 长窗与 predictor 聚类**：Huffman 多 pass 已完成（§4「已补齐」），
   剩余差距主要在 predictor 选择与分组聚类，而不是熵编码。
2. **VP8 行级流式解码（4B）**：`WebpRowSource` 的 VP8 分支已行增量（窗口化重建/输出
   平面 + 行对 RGB + ALPH 行增量，见 `PerfReport.md` §6.7）。
3. **色度模式选择还不是 RD**：`ChooseMode8` 的 4 个 8×8 模式只比**预测域** SSE，
   不看量化后的重建。平坦色块上这会选错——实测 256² 纯色 q70：DC 模式 pred=128、
   重建 102（与源一致），TM 模式的预测 SSE 更低但 pred=129、重建 103（偏 1 格）。
   改成「预测 + 量化 + 重建后比 SSE」应能再吃掉一部分平坦色偏差，代价是每宏块多
   4 次色度变换（需要按 method 分档，参考 libwebp `MBAnalyzeBestUVMode` 的取舍）。
4. **λ 与分段参数继续标定**：`ui` q90 已从 1.094× 降到 0.930×（见 §2 复核），
   但 `ui` q50 仍是唯一体积大于 libwebp 的档（1.077×，PSNR 低 0.80 dB）——
   该档的 λ 与段 delta 需要单独扫参。
5. **更大语料基准**：当前 24 组（+ `solid` 共 28 组）是 6~7 类合成/固定图，
   结论仍需真实照片集与截图集复核；另外「同 nominal q 差 2 档」意味着跨编码器比
   PSNR/体积应在**匹配 PSNR** 下做，BD-rate 测量台还没建。

已补齐（2026-11-05）：
- **系数 trellis**（§3.6）、**4 段分段量化重做**（§3.5）、**滤波强度 RD + 按段 lf delta**（§3.7）。
- **VP8L 无损多 pass**：首遍实际码长重算 Huffman + 2 轮精化（`PerfReport.md` §6.6）。
- **VP8L 行级流式解码**：`Vp8LRowDecoder` + 流式 RIFF 解析（`PerfReport.md` §6.6）。
- **VP8 行级流式解码**：`Vp8Decoder` 窗口模式 + `Vp8RowDecoder` + `AlphRowSource`
  （`PerfReport.md` §6.7）。

已补齐（2026-11-04）：
- 动图**逐帧惰性解码**：`WebpDecoder.EnumerateFrames` 每次只合成并返回当前帧快照，
  枚举器自身仅保留当前画布与上一帧 disposal 状态（O(画布)），不再为整段动图驻留
  O(帧数 × 画布)；`DecodeAnimation` 仍返回完整帧数组以保持既有 API。
  仅取末帧的 `DecodeRgba` / `DecodeRgbaInto` 也改走惰性路径。
  `WebpDecoder.ReadAnimationInfo` 只解析容器/ANMF 头即可得到画布尺寸、帧数与循环次数。

## 5. 踩过的坑

- **B_PRED 模式树写错一位就整体错位**：解码端 `kBModesProba` 的树里 B_HE 需要
  `p0..p2=1, p3=0, p4=0` 共 5 位，写侧曾漏掉最后一位。表现是 64×64 q75 的 PSNR 从
  40.7 掉到 12.0 dB，而两支解码器（我方 + libwebp）互相一致——位流合语法，只是模式读错。
  定位方法是给布尔编/解码器加位级 trace（记录 `(bit, prob, 语法段)`），第 1364 位处
  编码端用 `p[0][3][0]=56`、解码端用 `p[1][9][4]=197`，由此反推出「解码端多读了一位」。
  现已把模式树抽成 `Vp8ModeTree` 单一实现，并加全组合往返测试。

- **单值 setter 手写构造参数会静默丢字段**：`WebpEncoderOptions` 有四项目，而
  `WebpEncoderAdapter(.Rgba)` 的 Quality / Method / ConcurrencyStrategy 三个 setter
  各自写 `new WebpEncoderOptions(...)`，末尾的 `lossless` 有默认值 `false`，编译期
  毫无提示。后果是 `adapter.Lossless = true` 之后只要再设一次 `Quality`，产物就从
  VP8L 静默退回 VP8 有损——字节数变了，但没有任何异常或警告。现在 setter 统一用
  `Options with { ... }`（`WebpEncoderOptions` 为此改成 `readonly record struct`），
  `WebpEncoderOptionsTests` 对 6 条 setter 逐个固定「其余字段不变」。

- **「平坦」的判定要落在「有东西可省」的宏块上**：segmentation 第一次实现按源亮度
  方差 < 1 圈平坦宏块——但方差 ≈ 0 的宏块残差全零、本来就走 skip，粗化它的量化步长
  什么都省不到（§3.5）。没有对照实测的「合理改动」可能只是给位流加开销；
  体积/画质结论必须带 24 组对照数据。

- **文档漂移是真实的回归源**：`WebpDecoder` 类头一度写着「仅剩 ALPH level-reduction
  与 VP8 非关键帧两类不支持」，而 ALPH 的 `preprocessing` 0/1 早已支持、四种预测滤波
  后来也补齐了。`WebpContainerKind.Vp8` 的注释同样停在「本批不支持解码」。这类注释
  会误导调用方把正常输入当损坏数据，现在改为按 `WebpUnsupportedException` 的实际抛出点
  列举，并注明「修改时请核对抛出点，不要凭印象写」。
- **i4x4 的重建与模式选择必须逐块交错**：子块 n 的预测要读已重建的 n−1 / n−4，
  不能先算完 16 个子块的 SSE 再统一变换（那不成立）。因此「先判定再选路」不可能省掉
  被否决宏块的重复工作。
- **量化取整口径不一致，症状是「位流合法但画质反常」**：`ui`/`a_text` 这类纯色块多的
  内容，色度 DC 残差长期停在 ±1~2。按四舍五入（0.5）取整会把它推到相邻电平，重建
  反向过冲，下一块再跳回来——1024² 纯色 1.8 KB → 4.2 KB 且 PSNR 更低，而两支解码器
  互相一致、也没有任何语法错误。libwebp 的 `kBiasMatrices` 就是这条死区边界的参考
  口径（§3.8）。教训：**「能正常解码」不等于「量化口径对」**，平坦区的体积/PSNR 反常
  要先怀疑取整，而不是 λ。

- **DC 的「系数域最优」不等于「像素域最优」**：`DcRecon = (level·dq + 4) >> 3` 把线性
  的系数比映射成阶梯，dq ≥ 25 时一级就跳 3~4 个灰度级，`dq = 13` 时一级跳 2 格而系数域
  只够 0.62 个电平。按系数比取整会在「该跳还是不跳」之间逐块抖动。另外 `(dc+4) >> 3`
  正负不对称（dc = 204 → +26 / −25），误差必须按带符号的真实重建量算，取绝对值会差一格。

- **判据本身也可能是错的**：纯色回归测试一度用「整帧通道极差 ≤ 2」当作平坦判据，
  实际 libwebp 在同一 q、同一输入下极差**同样**是 5（主值 175 + 172/174/177 散点，
  我方的偏差来自色度 DC 单电平 4 档粒度 × 1.596 的 R 放大）。极差把量化粒度与环内
  滤波一起算成回归，真正对准机制的判据是「色度非零系数不随宏块增长」+「单一主值
  覆盖 ≥98% 像素」。写回归测试前先用参考实现跑一遍同样判据，能省掉一轮误判。

- **`top_right` 的三个写入位置是第 3/7/11 行右侧**（对应 C 里 `top_right` 指针按 BPS
  步进），不是第 0/4/8 行；最右列宏块要把上一行右侧 padding 归一化为边缘像素，
  否则下次读到陈旧值。

## 6. effort 档位（method 0..6）：默认对齐 libwebp 的编码工作量

`WebpEncoderOptions.Method` 过去只是兼容占位参数（"不影响产物"），现在是真的 effort
档位。目标是让默认路径的**耗时**接近 libwebp，而不是保住输出字节或压缩率——
两档产物都是合法可解码的 WebP，区别只在耗时与体积。

| 档位 | 有损 VP8 | 无损 VP8L / ALPH |
| --- | --- | --- |
| **0..4（默认，对齐 libwebp 默认 method=4）** | 单遍写位流（帧头用默认概率表，不写 1056 项更新）、标量量化替代 6 电平 trellis、i4x4 只取预测域 SSE 最优模式、滤波强度按 q 查表、ALPH 用采样估计选滤波 | 单候选；predictor 只按一次残差熵排序，不做逐候选整图 LZ77 复评与逐 tile 模式搜索；1 轮真实码长精化；单组 Huffman 表；首遍 copy 占比 <0.1% 时跳过精化 |
| **5..6** | 两遍概率自适应 + 决策重放、全 trellis、i4x4 三候选 RD 复评、滤波强度/分段 delta 实测评分 | 8 候选择优、2 轮精化、meta-Huffman 分组、ALPH 四种滤波真实试排 |

接线：`WebpEncoderOptions.Method` → `WebpCodec` → `WebpEncoder.EncodeRgba` /
`EncodeLossyRgba` 的 `method` 重载 → `Vp8Encoder.Encode` / `Vp8LEncoderOptions.AutoFast`。
新增 public 重载 `EncodeRgba(byte[], int, int, int method)` 与
`EncodeLossyRgba(byte[], int, int, float quality, int method)` 供直接指定档位。

**测试契约**：压缩率护栏（`Full_SizeWithin35PercentOfLibWebp`、
`AutoSelection_MatchesFullCandidateEnumeration`、有损体积 ≤1.5× 对拍）显式绑定
method=6；快档只验位流合法性、双解码器一致性、PSNR ≤2dB 与同档确定性。
`OptimizeWebpTests.WebpEncoderOptions_MethodSelectsEffortDeterministically`
取代原来的 "MethodHasNoEffectOnOutput"。

**同进程实测**（1024²、q75、3 次中位；libwebp 用简易 API 即 method=4）：
有损快档/原生耗时比 photo 0.49×、gradient 0.75×、ui 0.65×、noise 0.94×、
alpha 0.29×；无损 0.83× / 0.66× / 0.72× / 2.10× / 0.62×。
改动前（完整档作为默认）对应 3.4～18.8×。体积：有损 1.085～1.495× 原生，
无损除结构化渐变 4.4× 外均在 1.0～1.2×（256×192 渐变快档 166B，优于原生 190B）。
唯一剩余明显差距是纯随机噪声无损（2.10×）：LZ77 完全无收益，
libwebp 会更快 bail out，后续可考虑 literal-only 快路径。
复现探针见 `.perf/EffortProbe`（gitignored，与 GapProbe 同口径样本）。
